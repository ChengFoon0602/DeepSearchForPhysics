## 二、项目 Debug 方法论（12 条可迁移经验）

> 来源：学习日记.md

1. **先定位问题层级**：是「链路问题」（事件流不完整）还是「模型行为问题」（模型没按预期做事）？链路问题看日志事件，模型问题看 prompt 和产物。
2. **看真实产物，不要只看日志**：公式渲染问题，打开生成的 md 文件看内容；文件生成问题，看 output 目录里到底有没有文件。
3. **读完整 prompt，别只读自己改的部分**：模型行为不稳，第一嫌疑是 prompt 自相矛盾（模型对矛盾规则随机站队）。
4. **框架报错 = 答案**：认真读报错原文，它通常直接告诉你该用什么类、什么约束。用 `inspect.signature()` 确认 API。
5. **5 秒实证 > 猜**：sys.path 行为、路由优先级这类，写个最小复现跑一下，结论靠实验不靠记忆。
6. **区分上游错误和代码 bug**：网络层错误先重试；重试就好 = 瞬断，别改代码。
7. **测试要覆盖"错误用法"**：用错误方法访问 API 会暴露路由优先级，用 TestClient 能暴露 TestClient 独有的问题（记得和真实服务器对照）。
8. **一个原因一个原因排除**：SqliteSaver 的报错链是逐步收窄的——每修一个，报错就前进到下一个更具体的约束。
9. **异步状态必须设计终态恢复路径**：onclose / onerror / 超时看门狗。前端异步流程问自己三个问题——正常完成怎么办？报错怎么办？**断连 / 无响应怎么办**？最后一个是永远要补的兜底。
10. **前端"没反应"先分客户端 vs 服务器侧**：纯客户端按钮能用、触发请求的按钮不能用 → 问题在服务端。验证前端用 `file://` 绕过服务器，对比"全新实例 vs 当前实例"定位代码还是环境。
11. **理解系统的"记忆边界"**：记住什么、不记住什么，是设计决策。诊断"记不住"，先确认边界在哪一层（线程级 / 会话级 / 全局级）。
12. **新项目先写 CLAUDE.md**：可复用项目的第一个交付物，让任何未来会话一进目录就接上。

## 三、具体踩坑问题实录

> 来源：学习日记.md「踩坑实录」章节。以下按问题编号整理。

### 问题 1：主智能体"就绪待命"，不干活

- **现象**：发"搜索一下最近 AI Agent 领域的最新进展"，模型回"工作目录已就绪，当前为空目录，等待任务"，没调用任何工具，也没生成文件。
- **排查**：看服务器日志——`session_created` 有、`loop: True` 有，但**没有任何 `assistant_call` / `tool_start`**。
- **根因**：`run_deep_agent` 把一段【工作环境指令】追加到**每次** query 后面，内容写得像系统提示词（"系统会提供工作目录…规则 1-4"）。模型把整条消息误读成"初始化握手"，于是自我介绍、等待任务。
- **解决**：换更明确、带产出物的 query（也建议走 Swagger，避免 PowerShell 中文编码干扰）。
- **方法论**：**用"有没有调用工具"来区分「链路问题」还是「模型行为问题」**。

### 问题 2：生成的 Markdown 里公式渲染不出来

- **根因**：模型输出的是 LaTeX 原生分隔符 `\(...\)` / `\[...\]`，但 Markdown 生态的渲染器（Typora、VS Code 预览）只认 MathJax 风格的 `$...$` / `$$...$$`。
- **解决**：prompts.yml 加规则"行内公式用 `$...$`，独立公式用 `$$...$$`，严禁 `\(...\)`"。网页端则引入 KaTeX + marked 渲染。
- **方法论**：**区分"语法"和"分隔符"两个层面**。看产物、看渲染器的约定，别先怀疑 LaTeX 本身。

### 问题 3：网络瞬断问题（RemoteDisconnected）

- **现象**：服务器控制台 `[Monitor:error] 执行主智能发生异常信息：('Connection aborted.', RemoteDisconnected('Remote end closed connection without response'))`。
- **排查**：`RemoteDisconnected` 是"连接被对端关闭、无响应"，是**网络层**错误，不是 401/404（那是鉴权/模型问题）。重试一次即好 → 确认是瞬断。
- **根因**：DeepSeek 服务端抖动 / 网络瞬断 / 长连接复用被服务端关闭。
- **解决**：重试。若频繁，给 `llm.py` 的 `init_chat_model` 加 `max_retries=3, timeout=60`（只重试 HTTP 请求本身，幂等安全）。
- **方法论**：**先区分上游错误和代码 bug**。网络层错误（RemoteDisconnected/Timeout）先重试；如果重试就好，别改代码。要区分：401/403=鉴权，404=配置错，RemoteDisconnected=网络。

### 问题 9：前端"记录"按钮点击没反应（异步状态卡死）

- **排查**：先读代码确认接线 → 再追状态流转——发现 `busy` 只有 `task_result` / `error` 两个事件能重置，但页面**没有 `onclose` 处理、没有超时兜底**。
- **根因**：`send()` 里 `busy = true; 按钮 disabled` 之后，若 WebSocket 中途断开（调试时重启过服务器 / 网络抖动），两个终态事件都不会来 → `busy` 永远为 `true` → 按钮永远 disabled。**连接断开是静默的，页面根本不知道**。
- **解决**：四个兜底——① `ws.onclose` 里 `if(busy) finish()` 并提示"连接已断开"；② `ws.onerror` 同样重置；③ 5 分钟看门狗 `setTimeout`（`finish()` 时清除）；④「新会话」也重置 busy。

### 问题 10：点「记录」按钮没反应（空输入静默返回 + 坏服务器实例）

- **根因**：① 空输入 + 误导性文案（用户实际体验）；② SqliteSaver 调试期留下的坏服务器实例（独立、真实）。
- **解决**：① 按钮文案「记录」→「发送」；② 干净重启服务器（叉掉窗口 → 确认端口释放 → `python -m api.server`）。

### 问题 11：agent 记不住之前的会话——记忆是线程级的

- **根因**：**agent 的记忆是"线程级"的**：只有当前 `thread_id` 的检查点 + 当前工作目录。新线程 = 全新上下文 + 空目录。跨线程隔离是刻意的安全设计。
- **方法论**：**理解系统的"记忆边界"**——它记住什么、不记住什么，是设计决策不是 bug。诊断"为什么记不住"，先确认边界在哪一层（线程级 / 会话级 / 全局级）。

### 问题 12：新会话找不到项目上下文——缺 CLAUDE.md

- **根因**：**"约束先行"原则没落实**——搭了整个项目却没写项目说明书。
- **解决**：补一个项目 CLAUDE.md（项目是什么、启动命令、文件地图、已知坑、学习日记位置）。
- **方法论**：**可复用项目的第一个交付物不是代码，是 CLAUDE.md**。它让任何未来的会话（包括几个月后的自己）一进目录就能接上，不靠对话记忆。

### 问题 13：langchain `@tool` 装饰的不是普通函数

- **现象**：自检脚本 `search_knowledge_base("复摆周期公式", top_k=3)` 直接 `TypeError: 'StructuredTool' object is not callable`。
- **排查**：报错本身就是答案——`@tool` 返回的是 `StructuredTool` 实例，不是函数。
- **解决**：用 `.invoke({'query':..., 'top_k':...})`（或 `.func(...)`）调用。
- **方法论**：**framework 包装后的对象先看类型**。别假设装饰器返回的还是原来的签名，`type()` / `dir()` 看一眼再写调用代码。

### 问题 14：`from agent.main_agent import main_agent` 导入失败

- **根因**：模块导出的是 `_main_agent`（懒加载全局）+ `get_main_agent()` 工厂，**没有** `main_agent` 这个名字。自检命令写错了。
- **解决**：自检用 `import agent.main_agent`（能 import 就说明链路通），或 `from agent.main_agent import get_main_agent`。
- **方法论**：**文档里的命令也会过期**。重跑旧命令报错时，先读源码看导出名，别硬猜。

### 问题 15：YAML key 改名必须和代码 import 原子落地

- **现象**：`knowledge_base_agent.py` 改成 `sub_agents_content['kb']` 后，prompts.yml 还没改前 import 直接 KeyError。
- **根因**：两个文件强耦合——代码要的 key 和 YAML 里的 key 必须同时改。
- **解决**：一次性把 `prompts.yml` 的 `ragflow:`→`kb:` 和 `knowledge_base_agent.py` 一起改完，再重启。
- **方法论**：**配置与消费它的代码是一组变更，不是两件事**。改配置必搜所有消费方（grep key 名），确认全链路一致再动。

### 两个"README 没告诉你"的硬事实

1. **启动命令是错的**：README 写 `python api/server.py`。实际跑会 `ModuleNotFoundError: No module named 'agent'`。原因：`python 脚本路径` 时 `sys.path[0]` 指向脚本所在目录（`api/`），项目根目录不在 path 上。正确：`python -m api.server`。排查手段：5 秒实证。
2. **"数据库/RAGFlow 可选"只指配置可选，不是依赖包可选**：`main_agent.py` import 时就硬加载 `mysql.connector`、`ragflow_sdk`、`tavily`、`langchain-openai`。所以包必须全装，`.env` 的 key 才可以不填。

### AsyncSqliteSaver 报错链（必须活在事件循环里）

| 尝试 | 报错 | 说明 |
|---|---|---|
| ① 同步 `SqliteSaver` + `check_same_thread=False` | `The SqliteSaver does not support async methods. Consider using AsyncSqliteSaver` | 图用 `astream()` 异步执行，同步 saver 不支持异步方法 |
| ② `AsyncSqliteSaver` 在模块级建 | `RuntimeError: no running event loop` | `AsyncSqliteSaver.__init__` 里调用 `asyncio.get_running_loop()`——**必须在运行中的事件循环里构造** |

- **方法论**：**框架报错要认真读，报错本身就是答案**。**架构约束（要 running loop）不是 bug，是设计**——它逼你把"模块级构建"改成"循环内懒加载"，这是正确方向。

## 四、复摆实验相关易错点（来源：复摆动力学笔记.md）

### 常见测量误差来源（5 条）

1. 摆角过大：超过 $5°$ 需做大角度修正；
2. 转轴摩擦与空气阻力：振幅衰减使周期测量偏大；
3. 悬挂轴不水平或刀口不稳：产生非摆动自由度；
4. 周期计数的起止时刻选取：应取过平衡位置时刻而非振幅端；
5. $d$ 的测量误差：$d$ 较小时对 $T$ 的敏感度高（$d \to 0$ 时 $T \to \infty$，无法摆动）。

### 大角度修正（非小角度摆动）

小角度近似 $\sin\theta \approx \theta$ 在 $\theta$ 较大时失效。精确解用第一类完全椭圆积分 $K(k)$：

$$
T = T_0 \cdot \frac{2}{\pi} K\!\left(\sin\frac{\theta_0}{2}\right)
$$

展开到 $\theta_0^4$ 项：$T \approx T_0\left(1 + \frac{\theta_0^2}{16} + \frac{11\theta_0^4}{3072} + \cdots\right)$。当 $\theta_0 = 10°$ 时，修正项约 $0.19\%$；$\theta_0 = 30°$ 时约 $1.7\%$。**高精度实验必须做此项修正**。

### 阻尼与能量

考虑空气阻力（近似线性阻尼 $\propto \dot\theta$），振幅按指数衰减，周期略有增大（阻尼修正 $T \approx T_0/\sqrt{1-\zeta^2}$，$\zeta$ 为阻尼比）。
